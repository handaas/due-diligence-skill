# 尽调报告内容规范（事实核查版）

默认 direct-mcp 只发布可追溯事实、上游原始口径和数据缺口；不发布未经验证的自定义综合分、专项雷达或由数量直接推导的强弱结论。

## 一、章节与字段

1. 查询对象与口径：主体确认状态、匹配方式、覆盖域、时间、局限。
2. 数据总览：工商/投资/专利/招聘/司法/经营事实指标，每项带口径提示。
3. 核心分析：工商、股东、对外投资、诉讼结构、风险维度、开庭明细、经营、专利、招聘；空章节跳过。
4. 代表性记录：只复述同报告事实，不重新计算。
5. 特征与洞察：证据字段 + 解释 + 核验边界。
6. 数据口径与来源。

## 二、内容整理（原始值 → 标签 → 证据）

| 原始字段 | 规范展示 | 证据位置 | 禁止 |
| --- | --- | --- | --- |
| `caTotal` / `法院公告数` | 法院公告总数 | `dd_litigation` | 改写成“案件/公告总数” |
| `caLianTotal` / `立案公告数` | 立案公告总数 | dd_litigation | 与开庭公告相加 |
| `caKaitingTotal` / `开庭公告数` | 开庭公告总数 | dd_litigation / metrics | 冒充去重案件数 |
| `jdTotal` / `裁判文书数` | 裁判文书总数 | dd_litigation | 与公告数合并 |
| `enforcementTotal` / `被执行人记录数` | 被执行人总数 | dd_litigation / verdict | 与限制高消费混用 |
| `edTotal` / `失信被执行人数` | 失信被执行人总数 | dd_litigation / verdict | 缺省写 0 |
| `limitedTotal` / `限制高消费数` | 限制高消费总数 | dd_litigation / verdict / insights | 写到“被执行人”行，或用明细样本条数替代总数 |
| `risk_score` + `risk_level` | 原值 + “接口未说明阈值/方向” | metrics / 代表记录 | 反推低风险、编造等级冲突 |
| `patentCount` + 发明申请/授权 | 分列并写清占比分母 | dd_patent / insights | 把申请与授权合并为有效专利 |
| `recruitingCurrentCount` / `LastThreeMonthCount` | 同值时合并观察并注明窗口不可区分 | dd_recruitment | 当作两个独立扩张信号 |

- 英文 key 转中文标签；金额、比例、日期保留上游精度；未知写“未返回”，不得写成 `0`。
- 明细展示条数与上游总量分别写清；样本/单页不得称全量。
- 诉讼章节、司法洞察与结论阻断项统一使用同一套上游分类汇总：缓存报告的中文字段与实时英文字段等价，明细样本条数不得替代总数，显式 `0` 保留为 `0`。

## 三、语义审校门禁

1. **相关性**：投资广度只表示关联暴露面；开庭/执行记录不等于主体败诉或违约；招聘只表示公开活动。
2. **主题归类**：诉讼类别、风险维度、专利类型必须按上游分类，不得把不同类别合并成“司法风险总数”或“创新实力”。
3. **同义合并**：仅在上游明确别名或字段含义一致时合并；不确定时保留原名并标“待核验”。
4. **主体口径**：名称与统一社会信用代码未同时确认时，全部记录只作“具名检索线索”，不归属、不评级。
5. **时间口径**：开庭/裁判/执行/招聘窗口分别标注；历史记录不得表述为当前状态。
6. **冲突处理**：上游等级、总量、明细不一致时并列展示并写“未能对账”，不推断原因、不擅自择一。
7. **置信度**：展示样本、单页预算、未纳入条数必须披露；不得把样本分布写成全量。
8. **保留风险**：未查询的司法/合规维度保留为缺口；负面/执行/失信记录不删除、不被投资或专利数量抵消。

## 四、离线复核

`compose_direct.apply_content_review(report, calls=None)` 对冻结报告做纯本地整理：用既有 `calls.json` 的 `numeric_evidence` 恢复开庭/法院公告/立案/裁判文书/被执行/失信/限高分类，修正风险等级措辞与指标提示，不调用 MCP，不改证据文件。未保留的上游字段不得臆造，缺口语义写入 `caliber.limit`。

正常生成 `compose_direct.build_direct_payload`（`compose_fusion_report.py` 默认直连模式）在返回前调用同一函数；`calls=None` 时自动读取 `data["calls"]` / `_meta["calls"]` 中已有的调用证据并传入，不发起二次查询。主体未确认（`subject.resolved=false`）时即使存在同案调用证据也不把记录归属该主体或写入阻断项。整理只重算章节填充数并保留构建时声明的章节总数，缺失维度不会被折叠成 100% 覆盖。诉讼分类汇总由 `cross_analysis._litigation_summary` 统一读取：实时英文字段与缓存中文字段（`法院公告数` / `立案公告数` / `开庭公告数` / `裁判文书数` / `被执行人记录数` / `失信被执行人数` / `限制高消费数`）同口径，分类不合并、样本不冒总量、`0` 不被丢弃。
